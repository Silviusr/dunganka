# Dunganka Implementation Plan

**Goal:** Runnable Django portfolio demo with a real order database and staff administration.
**Architecture:** Server-rendered pages, session cart, validated checkout, transactional order creation and Django admin. All menu content is illustrative.
**Tech Stack:** Python 3.13, Django 5.2 LTS, SQLite, vanilla CSS/JS, WhiteNoise, Gunicorn.
**Spec:** ../specs/2026-11-05-dunganka-design.md

## Global Constraints
- Russian customer interface; Asia/Seoul dates; prices are integer KRW.
- Explicit demo notice, no actual fulfilment, no real customer data.
- Staff-only customer records, server-side totals, immutable order line snapshots.
- Django runs locally and in a portable container; Sites Workers cannot host this Python server.

## Review Focus
- Invalid quantities or unavailable dishes never produce a partial order.
- Past and excessively distant dispatch dates are rejected.
- Resubmission yields the same order; another session cannot read it.
- Cart/checkout errors stay visible and preserve customer input.
- Staff can update delivery costs and statuses without changing original line prices.
