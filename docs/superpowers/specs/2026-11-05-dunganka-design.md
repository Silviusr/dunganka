# Dunganka — первая версия сервиса заказов

## Задача

Сайт семейного кафе дунганской кухни в Инчоне помогает покупателю из другого города собрать заказ и передать контакты, адрес и желаемую дату отправки. Родители видят заявки в одном месте и согласовывают доставку с покупателем. Дополнительная цель — законченный проект для GitHub и портфолио.

Основание: прочитан исходный чат «Расскажи о моде на SaaS-проекты» от 3 ноября 2026 года. Этот документ различает прежние решения и новые предложения; он не означает, что приложение уже реализовано.

## Выбранный подход

Обсуждались два варианта: меню с копированием заказа в Instagram и сайт с сохранением заявок. Пользователь выбрал второй. Он требует закрытого кабинета и хранения данных, зато избавляет родителей от ручного переноса состава заказа, адреса и даты из переписки.

## Покупатель

- Меню: фотографии, названия, состав, порции или вес, цена в KRW, доступность.
- Корзина: количество, удаление позиций, сумма еды, комментарий.
- Заявка без регистрации: имя, телефон, адрес с индексом и квартирой, желаемая дата отправки. Контакт Instagram — предложение для удобства дальнейшего согласования.
- После успешного сохранения: номер заявки и сообщение, что кафе свяжется для подтверждения. Сообщение не обещает приём заказа к исполнению или оплату.
- Дата отправки и предполагаемое получение обозначаются отдельно. Со слов пользователя, посылка обычно приходит на следующий день; это не гарантия срока.

## Кабинет родителей

- Вход только для сотрудников; сведения о покупателях недоступны публично.
- Список и карточка заказа: позиции, количества, контакты, адрес, комментарий, дата отправки.
- Фильтр по дате отправки и статусу.
- Статусы: новый, подтверждён, готовится, отправлен. Возможность отмены — предложение для реализации.
- Стоимость доставки задаёт сотрудник при согласовании. До этого показывается только сумма еды и пояснение о доставке.
- Изменение цен, описаний и доступности блюд.
- Сохранение цены и названия позиции на момент оформления: последующее редактирование меню не меняет старые заказы.

## Предлагаемая реализация — ещё не выбрана пользователем

Для проекта, демонстрирующего Python, подходит Django с серверными HTML-шаблонами, небольшим количеством JavaScript и встроенной административной панелью. SQLite достаточно для локальной демонстрации; рабочее развёртывание потребует выбора хостинга и настройки постоянного хранилища. Альтернатива — приложение TypeScript для размещения через Sites. Выбор стека нужно зафиксировать до написания приложения; публичный запуск и запуск демонстрации — разные этапы.

Предложение по интерфейсу из прошлого обсуждения: русский язык, тёплый светлый фон, фотографии еды, удобство с телефона. Это предложение, не утверждённый визуальный макет.

## Границы первой версии

Без онлайн-оплаты, аккаунтов покупателей, подписки, автоматического расчёта почтовых тарифов и интеграции с Instagram Direct. Согласование происходит по контакту из заявки. Не следует обещать автоматические уведомления, пока они не реализованы.

В прошлом обсуждении извлечь меню и фотографии не удалось. Для настоящего запуска нужны актуальные блюда, порции, цены, фотографии, контакт кафе, допустимые даты отправки и сведения об упаковке, хранении и подготовке к подаче от родителей. Без них возможна только явно обозначенная демоверсия. Данные покупателей в публичный репозиторий и демо не включать.

## Что считать завершением

1. Покупатель с телефона может собрать и отправить заявку; она сохраняется и видна сотруднику.
2. Сервер проверяет доступность блюд, цены, количества и дату; сумму нельзя подменить через браузер.
3. Повторная отправка одной формы не создаёт дубликат заказа.
4. Посторонний не получает доступ к кабинету и данным заявок.
5. Проверены оформление, изменение меню, сохранение старой цены и работа статусов.
6. В GitHub находятся исходники, зависимости, пример конфигурации без секретов, инструкция запуска, описание ограничений, скриншоты и результаты проверок.
7. Демо доступно для просмотра; при отсутствии настоящего меню оно явно обозначено как демонстрация и не принимает реальные заказы.

## Следующие решения

Актуальное меню или демонстрационные данные; выбор реализации и хостинга; подтверждение визуального направления. Состав продукта уже выбран в исходном чате, повторно выбирать между Instagram-сообщением и сохранением заявок не требуется.
